# Supplier technical investigation

The department investigates the identified product, not a fixed series of marketplace buttons. It observes rendered text, images and the currently available controls, reasons about the next useful expansion, acts only on a validated current control, and observes again. A provider access policy supplies allowed domains and the product URL identity pattern; it does not supply an exploration sequence.

Only an AliExpress access adapter is currently connected. The engine also has a rendered fixture with a different URL structure and renamed menus. Neither that fixture nor an access policy proves live support for Temu or Alibaba; those providers require real access and acceptance tests.

Each visual attribute carries its source image, literal supporting text and optional SKU. Numerical facts retain source, excerpt and SKU. Page reads retain their collected literal documents and action checkpoint. Information from another listing is rejected. A global diagram cannot confirm every variant. Supplier assertions such as UV400 remain declarations, not independently verified certifications. Missing or conflicting evidence stays unresolved. Lens, bridge and temple sizes never fill whole-product dimensions.

`DDF_MEDIA_PAUSED=true` makes the pilot perform technical data work only and prevents the studio worker from running. Existing studio failures, reviews and the consumed repair nonce remain intact. The technical OCR revision adds component and material/model extraction; it checkpoints eight source images at a time. A failure or interruption is saved before the next paid attempt can be made. Never clear a failure checkpoint merely to retry.

`DDF_SUPPLIER_PAGE_ENABLED=true` opts into rendered exploration. It needs a working Chromium runtime. Exploration has a maximum of 18 observations and stops on access barriers, identity redirects, unsafe actions, repeated observations or invalid planner responses. It neither logs in nor submits forms, and external listing navigation is rejected. A blocked page read remains a checkpoint, not a completed technical sheet.

Acceptance: `node scripts/test-supplier-page.mjs` runs a rendered Chromium fixture with two menu names, a non-AliExpress access policy, technical text, an image-only source and an unrelated recommendation. CI installs Chromium and requires this test in addition to the existing quality gates. This tests the browser loop with a deterministic planner; live supplier access and real gateway planning still need operational verification.
